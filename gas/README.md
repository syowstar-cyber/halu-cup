# 点数報告 API の配置手順（Google Apps Script）

サーバを借りずに、Google アカウントだけで動く。所要 10 分。ブラウザで人が行う（Claude は代行しない）。
ドライブは使わない（保存先はスクリプト プロパティ）ので、ドライブへのアクセス許可は求められない。

## 1. スクリプトを作る

1. https://script.google.com を開き、「新しいプロジェクト」。
2. 左の `コード.gs` の中身を全部消し、この階層の `Code.gs` の中身を貼り付けて保存（Ctrl+S）。
3. プロジェクト名を「halu-cup-scores」など分かる名前にする。

## 2. キーは要らない

点数の送信もチェック共有もキーなしで受ける（2026-09-16 主催の指示。スマホで毎回数字を入れる手間をなくすため）。
以前の `REPORT_KEY`・`CHECK_KEY` はスクリプト プロパティから削除済み（2026-09-16）。
受け口の URL を知っていれば誰でも送れるが、プレイヤー名・対局・点数の範囲は検査し、送信履歴（`LOG`）に時刻が残る。

## 2b. 幹部のチェック共有

幹部用ページの設営・手配物・出発前チェック・確認事項のチェックは、この受け口に保存して幹部で共有する。
ページを開いたときに「幹部で共有中」と出れば動いている。「受け口が古い版です」と出たら `Code.gs` を新バージョンでデプロイする（「直したいとき」参照）。
保存先はスクリプト プロパティの `CHECKS`〜`CHECKS_4`（項目キー → 誰が・いつ。どれに入るかはキーで決まる）と、受付の出席チェック（キー `出席_P番号`）の `ATTEND`（1項目9KBの上限に収めるため。2026-10-11〜）。返すときは全部を合わせる。
置き場が上限に近づくと、チェックを付ける送信が「保存領域がいっぱい」で断られる（外すのは通る）。そのときは不要なチェックを外すか、エディタで `resetChecks`。
全消去はエディタで `resetChecks` を実行（`CHECKS`〜`CHECKS_4` と `ATTEND`。点数の `resetAll` では消えない）。

## 2c. 打ち上げ希望日の回答

参加者ページの7章のフォームから、名前・プレイヤーNo（分かれば）・①〜⑤を送る。同じ名前で送り直すと上書き、「回答を消す」で消える。
幹部用ページの8章に、人数の集計と回答の一覧が出る。保存先はスクリプト プロパティの `PARTY`（名前 → No・選択・時刻）。全消去はエディタで `resetParty`。
送るたび（上書き・取り消しを含む）に、履歴を `PARTY_LOG_1`, `PARTY_LOG_2`, … へ1件足す（今の番号は `PARTY_LOG_N`。2026-10-08〜）。履歴を消す関数はない（`resetParty` は `PARTY` だけを消す）。幹部用ページ8章の「回答の履歴」に出る。

## 2d. 出席者一覧（名前）

出席者の名前（主催の呼び名。2026-10-08 に LINE表示名から切り替え）と仮のプレイヤーNoは、スクリプト プロパティの `ROSTER`（P番号 → 名前）にだけ置く。
名前を変えると、打ち上げ希望（`PARTY`）も回答時刻ごと新しい名前へ移り、履歴に「名前を変更」と1件残る。
公開リポにも fp リポにも、名前のファイルは置かない（2026-09-17 主催の指示）。
登録は幹部用ページの8章「出席者一覧を貼り付け」（1行1人「P1 名前」）か、同じ表の名前欄を直接直す。
参加者ページの出席者一覧と打ち上げ希望の名前選択、幹部用ページの一覧は、開くたびにここから読む。
大会後に名前を消すときは、次の2つを行う（名前は `ROSTER` のほか `PARTY`・`PARTY_LOG_*`・`VIEWS`、幹部の名前はチェックの `CHECKS` にも残る）。
1. エディタで `resetRoster`・`resetParty`・`resetViews`・`resetChecks`・`resetPro`・`resetBirth` を実行する。
2. 「プロジェクトの設定」→「スクリプト プロパティ」から `PARTY_LOG_1`… と `PARTY_LOG_N` を手で消す。

## 2f. 生年月日（同点のときだけ・2026-10-11〜）

同点は年齢が上の方が上位。同点が出たら、幹部用ページ11章「当日の出席者チェック」の生年月日欄に、その人たちの分だけ入れる。
保存先はスクリプト プロパティの `BIRTH`（プレイヤー → `YYYY-MM-DD`）。**生年月日そのものは GET でも送信の返事でも返さない**。
返すのは、入れた人どうしの年上からの順 `agerank`（1 が最年長・同じ日は同じ数）だけ。点数報告ページはこれで同点を年上から並べる（全員の画面で同じ）。
幹部用ページには「入力済み」だけが出る。間違えたら「消す」で消して入れ直す。キーはないので、誰でも書き換えられる（点数と同じ扱い）。
合言葉は付けない（2026-10-11 主催の判断。幹部用ページで、幹部は全員が集計係のため）。そのため、自分で日付を何度も入れて返る上下と比べれば、入れた人の日付を絞り込める。大会が終わったらすぐ `resetBirth` で消す。
`resetBirth` は生年月日を消す前に、その時点の上下の順だけを `AGERANK_FROZEN` に固定し、以後は返し続ける（大会後に順位や準決勝のメンバーが元に戻らないように）。固定した後は生年月日の入力を断る（ページには「締め切り済み」と出る）。
もう一度受け付けたいときは、エディタで `reopenBirth`（固定した順を捨てる）。打ち上げの振り分けは最終順位で決めるので、`resetBirth` はその後でも順位は変わらない。
受付の出席チェックは、チェック共有のキー `出席_P番号`（置き場は `ATTEND`）に残る。全消去はエディタで `resetBirth`（生年月日）・`resetChecks`（出席を含むチェック）。

## 2e. 本田プロ確認事項の回答（2026-10-10〜）

本田プロ用ページ（`pro/index.html`）の6章から、質問1〜8（幹部用MD 14章の連-1〜8）への回答と、送った人の名前・立場を受ける。
保存先はスクリプト プロパティの `PRO_ANS`（番号 → 選択・補足・名前・時刻。同じ番号は上書き）。送信履歴は `PRO_LOG`（時刻・名前・番号だけ・直近50件）。
**中身は GET で返さない**（到着時刻・前後の予定を公開しないため）。ページに出るのは項目ごとの「送信済み（時刻）」だけ。
届くたびに、このスクリプトの持ち主の Gmail へ回答の全文をメールで送る（1日30通まで。数は `PRO_MAIL`）。メールが送れなくても回答は保存される。
このため、デプロイのとき「メールの送信」と「メールアドレスの参照」の許可を求められる。自分のアカウントで許可する。
メールを見落としたときは、「プロジェクトの設定」→「スクリプト プロパティ」の `PRO_ANS` で中身を見られる。全消去はエディタで `resetPro`。
キーはないので、名前は自己申告。心当たりのない回答は、連盟など元の窓口で確かめる。

## 3. ウェブアプリとして公開する

1. 右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」。
2. 説明は任意。「次のユーザーとして実行」= **自分**、「アクセスできるユーザー」= **全員**。
3. 「デプロイ」→ 権限の確認が出たら自分のアカウントで許可する（ドライブの権限は要求されない。2026-10-10 からメール送信の権限を求められる＝2e）。
4. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピーする。

## 4. ページに URL を入れる

`score/config.js` の `window.HALU_API = ""` の引用符の中に、コピーした URL を貼る。
`git commit` → `git push` で反映される。

## 5. 動作確認

`https://syowstar-cyber.github.io/halu-cup/score/` を開き、半荘と卓を選んで点棒を入れて送信する。
表に反映されれば完了。JSON の実体はスクリプト プロパティの `PLAYERS`（点数）と `LOG`（送信履歴・直近120件）。丸ごと取り出すときは受け口の URL を GET で開く（ページの「JSONをコピー」は 2026-10-10 に廃止）。

チョンボ回数はスクリプト プロパティの `CHOMBO`（プレイヤー → 半荘 → 回数）。点棒と一緒に送られ、`resetAll` で点数と一緒に消える（2026-09-25）。同日にチョンボを満貫払いへ変えたため、ページからは送らない（受け口は受けられるまま残す）。

## 直したいとき

- 点数の訂正: 同じプレイヤー・同じ半荘でもう一度送ると上書きされる。
- 取り消し: ページの「取り消し」ボタン（null に戻す）。
- 全消去: エディタで関数 `resetAll` を選んで「実行」。
- `Code.gs` を直したら「デプロイ」→「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→ デプロイ。URL は変わらない。
